# QuickSell 交易助手设计与开发计划

更新：2026-10-29。目标为本机正式版内置 ModLoader；不上传创意工坊。

## 已确认的产品行为

- 顾客收货平板底部：「一键上货」「出售 X 件物品」复用原版购买/批发按钮布局（x19/287、宽256、高42、间距12 UI单位）。左键上货，右键设置。保留原版成交、预算和顾客规则。
- 设置使用可读的独立尺寸与原版纸色、字体、边框、按钮；四页：供货区、物品保护、显示提示、选货规则。不能继承平板的缩小倍率。
- 日常刷新不得反复销毁重建操作栏、页面或高亮。列表只在主动扫描、页签切换、实际增删时更新；开关更新自身。
- 无顾客时通过原版 Mod 配置中的「打开交易助手」入口进入同一设置，不新增库存排序菜单或容器右键菜单项。
- 供货区：打开页面或刷新时分帧发现自有储物容器，无需打开容器。支持加入、移除；同名容器显示路径和编号。供货区记录按存档/周目隔离。
- 物品保护：显示台面自有物品，可逐个加入保护；同类不同实例分别管理，整叠为一项。另列已保护物品，移回仓库仍受保护。
- 保护仅针对实例，不做按类型批量禁售。自动上货跳过保护物品；批量出售遇保护物品只弹一次确认，确认后整批成交，取消则不成交；单件出售不额外确认。实际成交后移除已售实例记录。容器连带出售也检查内部保护内容。原版超预算确认与保护确认合并，不能连续双重弹窗。
- 提示为按住快捷键显示、松开隐藏，默认未绑定；设置中可修改单键/组合键，分别选择顾客需求、赃物、违禁品（初始均开）。输入文字、绑定按键、设置打开、游戏失焦时不显示。2026-10-29 补充：容器汇总内部物品状态，关闭内容不绘制独立标记。
- 需求为绿色四角；赃物为琥珀标签；违禁品为红色三角。独立叠加、不染色、不动画、不遮数量和固定标记。只处理可见商品，不透视关闭容器。绿色不代表预算足够。
- 选货：优先级「尽量用满预算」（默认）/「优先腾空间」；允许超预算关/5/10/20（默认关）；嵌套检索默认开；按需拆堆默认开。计算有界，不承诺数学最优。已固定、受保护、顾客拒收的商品排除，柜台已有商品计入预算；供货储物容器只取内容，不提取机器工作槽位。
- 拆堆必须保留状态；原生拆分不复制完整状态，未经验证的特殊堆叠只按整叠处理，不猜测复制属性。

## 底层约束

- 仅按实际交互启动任务，一个主线程调度入口共享约 1 ms 检索预算；预算是协作式的，原版快照/搬运调用不可中断。一个上货任务，刷新和提示任务可替换，不积压旧请求。
- 显式游标逐步遍历；每库存快照一次，去重库存与物品。GameGridInventory.childItems 会复制列表，禁止循环内反复读取。
- 高亮松键立即隐藏并取消未完成工作；物品显示状态变化时按需更新。无常驻全店索引、后台扫描或新依赖。
- 纯组合计算同样分帧、有状态上限；不在后台线程读取 Unity/游戏对象。实际搬运前重新检查所有权、保护、来源、顾客、预算和空间。
- 状态按 saveSlotId/runNumber 隔离；保护按实例唯一 ID；销毁/成交/切档清理运行时引用。配置错误不能静默吞掉。
- 只清理自己的补丁、对象、任务和订阅。失败要留诊断，不留下半启用状态。

## 开发顺序与验收

1. 文档、版本与原型基线；核对当前正式版 API。
2. 稳定操作栏、四页可读设置、原版配置入口；同一交易状态保持按钮实例，无空结果/取消闪动。
3. 共享分帧调度、供货区发现与配置隔离；关闭容器也可加入，嵌套来源不重复。
4. 实例保护与一次批量确认；单件不弹窗，成交清理，超预算合并提示，确认期间变更必须失效。
5. 按住提示、快捷键绑定、三种标记；失焦/松键/开设置立即隐藏；数量与固定覆盖不冲突。
6. 有界预算选货、腾空间、超预算选项、安全拆堆；不改变原版属性与成交行为。
7. 相关纯逻辑测试、编译、差异审查、部署备份与哈希核验、实机截图和日志；实机未通过的项目明确留待验收。

### 必测场景

- 连续上货、无候选、取消、切换顾客、空柜台、数量变化、关闭重开设置：操作栏与状态行不闪动。
- 设置的正常字号、窄屏/低分辨率下可达；按键绑定可取消/清除；每页均可关闭。
- 台面保护、仓库保护、单件成交、批量取消/确认、保护容器内容、原版预算不足确认。
- 同名容器、关闭容器、嵌套重叠、固定容器、机器槽位、存档/周目切换。
- 提示三项单开/叠加、无顾客、按住时移动旋转、松键、失焦，不显示关闭容器内部。
- 预算100对70/60/40应能优于单纯高价贪心；种类限制、单件限制、超预算0/5/10/20、特殊堆叠属性。
- 100/1000/10000实例压力样本，记录检索、单次调用、搬运、分配与任务总耗时；没有实测不能宣称不卡顿。

### 当前验证记录

- 纯选货测试：100/1000/10000 候选一次完整计算约 4/11/10 ms（独立控制台总时间，不是 Unity 单帧耗时；运行波动正常）。计算量限制与预算限制通过。
- 不操作游戏内成交来冒充自动验收。用户要求自行操作游戏；已停止电脑控制，等用户截图、日志反馈后补记原生 UI、保护成交和高亮验收。
- 特殊堆叠仅整叠处理；可拆商品须通过数量回调与报价比例检查。是否覆盖实际常用堆叠需实机验证。
- 设置入口利用原版 ModConfig 的一次性勾选请求；首次无需顾客，进入存档才可打开。
- 首次启动实机日志发现 1.3.0 每帧读取惰性 PlayerStore.Instance 导致主菜单提前构造对象并报错。1.3.1 已增加店铺库存就绪门槛（面板/快捷键也同样检查）；待退出后部署并重新验证。不能将此轮原生验收标为通过。
- 1.3.2 根据用户截图修正：实色纸面与描边分离；高亮挂在未旋转的物品 handler，并以 modifiedShape.globalWidth/globalHeight 定位；角标固定 7 UI 单位。容器按子树汇总状态，库存快照和子节点结果在本次检索复用。待实机确认。
- 1.3.2 编译零警告零错误，12项检查通过；新增直接调用正式版 GridShapeBuilder 的四方向、双翻转、非零位置测试，确认旋转后占格尺寸合同。测试仍不代替 Unity 实际绘制验收。
- 用户补充采用原版批发布局：按钮 x=19/287，宽256、高42、间距12 UI单位；替代此前按商品区域均分及16间距的方案。取消窄缝状态行，完成/失败使用原版通知与悬停详情。
