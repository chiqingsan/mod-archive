## 0. 一页纸（TL;DR）

**净水塔**是一台 3×3 的店铺机器，把「玩家自己的净水器」接入自动化流水线：

```
玩家容器（手动倒） ──> 待处理区 100L（固定容器）
                          │  净水器瓶槽为空时补水（优先待处理，其次水龙头，都没有就不动）
                          ▼
               净水器区 20×19（玩家放任意台原版净水器，每台自带电池、每夜自己净化）
                          │  塔在夜结收尾时检查每台净水器瓶槽里的水
                          │  达标 ──> 转移到「已处理区」600L 固定容器
                          ▼
               已处理区 600L（达标水）
                          ├─ 手动按钮灌装：1L / 3L / 6L / 20L / 60L（打印瓶 + 装水，扣电池区电）
                          └─ 空容器点塔：直接从 600L 灌满（不打印、不耗电）
                          ▼
               输出区（玩家自取，自行议价出售；塔不做自动售卖）
```

- **净水能力完全来自玩家净水器**：品质/性能/模块/电池都是玩家自己的投入；塔只做自动化接线（补水、查达标、抽走达标水）。
- **UV 槽**（净水箱内独立槽）：放入紫外线灯后，每次给净水器容器注水后自动 `OnUVUsed` 一次（灭微生物、零耗电零耐久）。
- **电池区 4×4**：合并成一个电量池，供塔的打印灌装用电（净化电由每台净水器的电池槽自理）。
- **目标档塔统一设置**：普通 9800 / 优质 9900（默认）/ 纯水 9990；纯水需要参与净化的每台净水器品质加成 ≥100。
- **实现不要求 0 Harmony（v0.6 用户定）**：需要反射就反射、要注入就注入；能走官方 API 的继续走（倒水/UV/贴标/打印/窗口），注册/上架/夜结兜底可用 Harmony Postfix。

## 1. 前置：净水到底和什么有关（正式版复核）

### 1.1 四种手段的真实作用

| 手段 | 实际作用 | 能不能把水抬到「纯水」 | 证据 |
|---|---|---|---|
| **净水器**（water_purifier） | 每夜按预算移除污染物（大颗粒优先，化学/重金属最后清），把纯度推到本机上限 | **唯一途径**。默认上限 9900，品质加成 ≥100 才 9990 | `MachinePurifier.cs`（PurifyContainer / GetMaxPurityCap） |
| **滤芯**（water_filter / adv / hydroreed，孔径 22） | 只在液体**转移**时按孔径截留：孔径 22 只能拦 particleSize≥22 的杂质（有机物 40、微塑料 25、物理 100、矿物 30），滤不掉重金属(12)/化学(2)；被滤掉的部分直接损失 | 不能。对矿物/大颗粒是精修 | `WaterHelper.cs:333-395`；孔径见 `AmenitiesItemDirectory.cs:418/436/457/538` |
| **紫外线灯**（uv_filter） | `OnUVUsed` 把微生物全部转成水，无耐久、无耗电；不能放水壶滤芯槽 | 不能（微生物之外不变） | `WaterHelper.cs:838-855`；`AmenitiesItemDirectory.cs:240` |
| **净水片**（water_tablet） | 氯化学片：清化学污染物到「总体积 0.7%」地板，剩余灭微生物；不补水、不动重金属/矿物/有机物 | 不能，0.7% 地板连 9900 都到不了 | `ChemicalHelper`（`CHLORINE_POTENCY=5.1`，15ml chlorine） |

**结论**：净水塔不复制净化公式，也不给净水器加 buff；塔只是把「净水器自己的净化流程」接成自动线。

### 1.2 净水器的原版行为（塔要复用的部分）

- 净水器每夜（`onCycleEndSlotItemFunc`）检查瓶槽（body storage 索引 2）里的液体容器：有电（4 电/夜）且容器非空 → 调 `MachinePurifier.PurifyContainer(machine, container)`（public static，`MachinePurifier.cs:114`）→ 只在真移除了污染物时才扣电。
- 纯度上限 = `10000 − round(100 × purityMult(品质加成))`：默认 **9900**；品质 ≥15→9915、≥25→9935、≥50→9965、≥75→9980、**≥100→9990**、≥200→10000。
- 每夜预算 = `(min(体积,10L)×3‰ + 25ml) × dirtBonus × 1.25`；dirtBonus 按当前纯度 9800:1 / 9400:2 / 8850:5 / 8000:10 / 6250:15 / 3750:20 线性插值。
- 净水器需要玩家在电池槽（索引 0）放电池（`power_source_item`）才有电；塔不供电。

## 2. 目标与非目标

### 2.1 目标

1. 玩家放下塔、放入净水器、手动倒一次脏水后，塔能自动循环补水 → 净水器自己净化 → 达标 → 存入 600L → 玩家灌装带走。
2. 水的「净化」始终是净水器的原始机制与原始成本（电、时间），塔只省操作、不省成本。
3. 可放多台净水器并行；单台净水器也能用。
4. 灌装规格 1L / 3L / 6L / 20L / 60L，电耗按原版瓶子打印机的电量-容量比例拟合。
5. 实现约束放开：不要求 0 Harmony（反射/注入随意），优先官方 API 与已验证的补丁点（v0.6）。

### 2.2 非目标（明确不做）

- ❌ 不做塔内净化（不调用 PurifyContainer，不替代净水器）——v0.3 方案作废。
- ❌ 不做自动售卖/自动卖顾客（灌装后玩家自行处理）；不接喷泉/议价自动成交。
- ❌ 不做滤芯仓（滤芯只在转移时生效，收益低；用户已定不做）。
- ❌ 不做净水片自动化。
- ❌ 不新增净化配方、不改原版数值。
- ❌ 不改水价与水质条件倍率。

### 3.3 夜间流水线（塔的收尾结算）

塔物品注册 `onCycleEndLateSlotItemFunc`（夜结的**后段**，`PlayerStore.cs:1728` 遍历调用；原版先例 `VendingFountainHelper.cs:103`）。这样顺序稳定为：

1. 游戏先跑所有机器（含每台净水器自己那一遍净化）；
2. **然后**塔做收尾：
   - **满则全停**：若 600L 达标容器已满（`GetFreeCapacity(600L容器) == 0`）→ **转运与补水一起停**，只刷新 UI 提示「已满，请灌装/取水」（用户定 v0.5；净水器里的水保持原样，继续由它自己净化）；
   - **检查达标**：对每台净水器的瓶槽容器，若 `GetWaterPurity ≥ 目标档门槛` → `TransferLiquid(净水器容器 → 已处理区 600L)`；
   - **空容器补水（单一水源）**：只对**检查为空的**净水器容器补一次水——待处理区 100L 有水 → `TransferLiquid(待处理容器 → 净水器容器)`（能倒多少倒多少、**不补满**）；待处理区空 → 若「自动水龙头」开关打开且已解锁 → `AddWater(净水器容器, 1, 9999999, useRange, 当日水质)`；两者都没有 → 什么也不做。**容器非空绝不补第二种水**（v0.6 用户定，避免混水）；
   - **UV**：若 UV 槽有灯，对本次被注水的每个净水器容器 `OnUVUsed` 一次；
   - 更新塔 UI（各容器水量、本夜注水/转运量、电池余量）。

> 为什么用 Late 而不是普通 onCycleEnd：普通阶段净水器与塔同批执行，顺序取决于 `FindAllItem` 的遍历顺序；Late 保证「先净水器、后塔」，上一夜的水当晚被检查/抽走，补水给下一夜净化。

## 4. 净水箱（净水器区 20×19）

### 4.1 玩家侧操作

- 把原版净水器放到 20×19 区域内任意空位（可放多台；占格数由净水器贴图决定，实机实测）。
- 每台净水器自己需要：
  1. 电池槽放电池（否则不运行，塔不供电）；
  2. 瓶槽放**液体容器**（净化在水容器里进行；没有容器就无法净化，塔的补水也无法进行）；
  3. 需要品质档时自己装模块（纯水需品质 ≥100）。
- 塔不修改净水器的任何配置，只往它的瓶槽容器里加水/抽水。
- **塔内可直接配置净水器（用户定）**：双击 20×19 里的净水器即打开它自己的窗口（放电池/瓶槽容器/模块），无需取出重放。【已确认】`ItemMouseDoubleClickHandler.ClickAction`：任意渲染中的 `GameItem` 只要 `contentWindow != null` 就 `Show`（`ItemMouseDoubleClickHandler.cs:143-153`、`OpenContentAction` :177-203），`RenderHandler.RaycastElement<GameItem>` 按 UI 元素命中、不限制嵌套层级；玩家也可把净水器拖出塔单独配置再放回。
- 瓶槽容器**玩家自备**（用户定）：塔不代配、不代买；没放容器或没放电池的净水器由塔跳过（D40）。
- **纯水不可达的净水器只做按键高亮标记（用户定 v0.6，D46）**：对品质加成→最高纯度达不到塔当前目标档的净水器，在净水器区里加高亮标记（参考「帮我上货」QuickSell 的高亮实现：`Hints.cs`/`HintArtwork.cs`/`HintBounds.cs`，PNG 内嵌 + ≤512×512 共享图集 + 四角 UV 按格贴合）；不弹窗、不警报、不阻止它继续净化（净化到极限后 `removed==0` 不扣电）。
- **便携净水器可放入但不生效（用户定 v0.6，D48）**：塔只处理 `water_purifier`；`portable_water_purifier` 放进 20×19 视为无效物品，跳过不报错。

## 5. 接水：待处理区与自动水龙头

### 5.1 待处理区怎么进水

- **玩家手动倒**（唯一入口）：**打开塔窗口后**与待处理 100L 容器交互 → 把玩家容器里的水 `TransferLiquid` 进待处理容器（≤ 剩余容量），容器剩余水留在玩家容器里。外部拿容器**点塔不会**往待处理区倒水（v0.6 用户定：外部交互只对 600L 储水区）。
- 待处理容器满（100L）后不再接收。
- 塔内不设「玩家容器槽」——用户明确：待处理容器是固定自带、玩家自己倒水。
- **单一水源（v0.6 用户定）**：待处理容器只在净水器瓶槽**为空**时才会被使用；待处理水不够灌满一个空容器时，**能倒多少倒多少、不补满**，也不拿水龙头水补差额。

### 5.2 自动水龙头

| 项 | 设计 |
|---|---|
| 开关 | 塔窗口一个布尔按钮「自动水龙头」，**默认关**（用户定 v0.6），状态存塔 tag（D19） |
| 解锁判定 | `EmporiumEntry.IsWaterTapUnlocked()`（public static，`EmporiumEntry.cs:490`）：`RUSTWATER_TAP` 或 `GUTTERFLOW_TAP` 已解锁 |
| 未解锁 | 开关置灰 + tooltip「需先解锁店铺水龙头」 |
| 水质 | `StoreStation.Instance.todayRustwaterPurity`（9000–9150）或 `todayGutterflowPurity`（8000–8999），每天开局重掷（`StoreStation.cs:69-70`、`:22-45`） |
| 取水方式 | 直接 `AddWater(净水器容器, 1, 9999999, useRange:true, 当日纯度, 当日纯度)`，**不经过** 100L 待处理容器（用户：待处理区有则先用待处理，没有才用水龙头） |

### 5.3 UV 灯

- UV 槽放 `uv_filter`；每次注水后对**本批被注水的容器**各 `OnUVUsed` 一次（microbe 全清转成水，无耐久消耗、无耗电）。
- 触发时机：补水完成后、下一夜净化之前（塔的 Late 回调里完成，净水器下一夜开始净化的是已杀菌的水）。

## 7. 灌装

### 7.1 两个入口

1. **按钮灌装（主入口）**：选择容量 → 「打印瓶子」+「装达标水」一步完成 → 输出一瓶满水瓶子到输出区。
2. **手动灌装（快捷入口）**：玩家拿**空液体容器点塔** → 直接从 600L 达标容器 `TransferLiquid` 灌满该容器（不打印、不耗电）。

### 7.2 容量档与容器

| 容量档 | 输出物品 | 来源 | 打印电耗（拟合） |
|---|---|---|---|
| 1L | **新增** `purifier_tower_bottle_1l`（1000ml，约 4 信用点底价） | 复用现有贴图 `bottled_water` | 7 |
| 3L | 原版 `water_pitcher`（3000ml） | 原版物品 | 15 |
| 6L | 原版 `water_jug`（6000ml） | 原版物品 | 27 |
| 20L | 原版 `water_tank`（20000ml，初始 20L） | 原版物品 | 83 |
| 60L | **新增** `purifier_tower_bottle_60l`（60000ml） | 复用现有贴图 `water_tank` | 243 |

- 新物品用现有贴图占位（用户确认），后续可换美术。
- 3L/6L/20L 复用原版容器：游戏里本来就存在、可被顾客/体积系统识别，风险最低。
- 打印不消耗材料（与原版瓶子打印机一致：`MachineBottlePrinter.TryPrint` 只扣电，不扣材料）。

### 7.3 电耗公式（用户定：拟合，容量越大性价比越高）

```
电 = round(3 + 0.004 × 容量ml)
```

| 容量 | 1L | 3L | 6L | 20L | 60L |
|---|---|---|---|---|---|
| 电（满瓶） | 7 | 15 | 27 | 83 | 243 |
| 电（半瓶示例：装 1/2） | 4 | 8 | 14 | 42 | 122 |

校准依据：原版瓶子打印机 450ml=4 电、750ml=6 电、2000ml=11 电（`MachineBottlePrinter.cs`）；公式在 750/2000 两点精确吻合，450ml 略高于实际（4.8→5），符合「越大越划算」。**半瓶时电耗按实际装水量计算**。

### 7.4 灌装流程（按钮）

```
点容量按钮
  → 检查：达标水 600L 余量 ≥ 10ml（D43）；输出区有空位；电池区总电量 ≥ 电耗
  → 生成空瓶物品（DirectoryMaster.Item(瓶id)）
  → 装水：TransferLiquid(600L 容器 → 瓶)，实际装水量 = min(规格容量, 600L 余量)
  → 扣电：按实际装水量从电池区合并池扣（TryRemoveEnergy）
  → 瓶入输出区（GraphUtils.TryAcceptAll）
  → 更新 UI
```

- 硬条件不满足时按钮置灰并 tooltip 说明原因（600L 为空 / 电量不足 / 输出区满）。
- **半瓶策略（用户定：半瓶也灌）**：600L 里有多少灌多少——实际装水量 = min(规格容量, 600L 余量)；瓶子按所选规格生成，装了实际水量，标签按实际水量计价；玩家可以之后再补满。电耗按**实际装水量**计算（满瓶时等于规格对应的电耗）。余量需 **≥ 10ml**（D43），不足时按钮置灰。
- 灌装后的瓶子**玩家自行处理**（拿走议价出售），塔不做自动售卖。

### 7.5 装瓶后的水质标签

- 灌装前对 600L 容器执行 `SetPresumedPurity(600L容器, GetWaterPurity(600L容器))`，保证标签 = 实际水质（避免 `SecData.GetMislabeledWaterWeight` 判假标）。
- 输出瓶继承 600L 容器的真实档位（`TransferLiquid` → `OnLiquidContainerPourInto` 自动继承并刷新 unitValue=40/L×体积）。

## 8. 目标档与品质

| 目标档 | 门槛（纯度） | 对应显示 | 前置条件 |
|---|---|---|---|
| 普通水 | 9800 | 98%–99% | 无（任何净水器都可达） |
| **优质水（默认）** | 9900 | 99%–99.9% | 无（原版净水器默认上限就是 9900） |
| 纯水 | 9990 | 99.9%+ | **每台参与净化的净水器品质加成 ≥100** |

- 目标档在塔窗口统一设置（用户定：塔统一一个目标）。
- 塔不修改净水器；对「品质加成→`GetMaxPurityCap` 等价值达不到当前目标档」的净水器，**只做按键高亮标记（依据 D46，参考 QuickSell 实现）**，不弹窗、不警报、不阻止运行。
- **不会平白耗电（v0.6 用户定）**：净水器到净化极限后 `removed==0`，当晚不扣电（已确认 `MachinePurifier.onCycleEndSlotItemFunc` 只在 `removed > 0` 时 `DrawPowerSource`）；高亮只是提示。
- 达标判定为**下限**：实际纯度 ≥ 门槛即转运；单遍净化越过更高档时按实际档位贴标，不伪造也不浪费。
- 品质来源：净水器自己的模块格（9 格，`MODULE_TYPE_UNIVERSAL`）。品质加成 ≥100 的常见方案：4×`system_fineness`（25%×4，代价性能-32/效率-60）、2×`system_capped_neural_core`（50%×2）、1×`system_uncapped_neural_core`（100%，违禁品）。

## 9. 夜间伪代码

```
// 塔：onCycleEndLateSlotItemFunc（游戏在所有机器结算之后调用）
OnTowerLateCycle(tower):
    if (tower 无电/不需要电) { /* 无操作，塔自身不耗电 */ }

    // 0) 600L 已满：转运与补水一起停，只提示（用户定 v0.5 / D42）
    if WaterHelper.GetFreeCapacity(达标水容器600L) == 0:
        UpdateTowerUI(tower)                  // 「已满，请灌装/取水」
        return

    // 1) 抽走达标水
    foreach (净水器 in 净水器区):
        c = MachineHelper.GetSlot(净水器, 2).childItem
        if c == null || !c.HasLiquid(): continue
        if WaterHelper.GetWaterPurity(c) >= 目标档门槛:
            WaterHelper.TransferLiquid(c, 达标水容器600L)        // 0 电
            SetPresumedPurity(达标水容器, GetWaterPurity(达标水容器))
            if WaterHelper.GetFreeCapacity(达标水容器600L) == 0: break   // 中途满：剩余水留到下次

    // 2) 空容器补水（单一水源：只在空的时候补一次，不混水、不补满；v0.6 用户定）
    foreach (净水器 in 净水器区):
        c = MachineHelper.GetSlot(净水器, 2).childItem
        if c == null: continue
        if WaterHelper.GetTotalVolume(c) > 0: continue       // 容器非空：这批水没净化完，不补第二种水
        if WaterHelper.GetTotalVolume(待处理容器100L) > 0:
            WaterHelper.TransferLiquid(待处理容器100L, c)     // 优先待处理水；能倒多少倒多少，不补满
        else if 开关打开 && EmporiumEntry.IsWaterTapUnlocked():
            WaterHelper.AddWater(c, 1, 9999999, useRange:true, 当日水质, 当日水质)   // 直接注水（灌满）
        else:
            continue                                          // 都没有：不动
        // 3) UV（注水后立即执行一次；下一夜净化前完成杀菌）
        if UV槽有灯: WaterHelper.OnUVUsed(c)

    // 4) 刷新 UI（水量、达标判定、电池余量）
    UpdateTowerUI(tower)
```

- 顺序保证：净水器自己那一遍净化发生在塔的 Late 回调之前（`PlayerStore.cs:1720` 普通段 → `:1728` 晚段）。
- 每台净水器每夜自己净化一次（4 电，来自它自己的电池）；塔不重复调用。

## 12. 数值平衡

### 12.1 一批水的节奏（单台净水器，瓶槽 6L）

以水龙头水（纯度约 8500）→ 优质 9900 为目标：

| 阶段 | 杂质（6L 中） | 单夜预算 | 约需夜数 |
|---|---|---|---|
| 8500 → 9400 | ≈540ml | 43ml×(≈7)×1.25≈376ml | 1–2 |
| 9400 → 9800 | ≈ 240ml | ×2×1.25≈108ml | 2 |
| 9800 → 9900 | ≈ 60ml | ×1×1.25≈54ml | 1–2 |
| 合计 | | | **约 4–6 夜**（从沟渠水 3500 起约 9–10 夜） |

- 多台净水器并行 → 吞吐线性增加；每个净水器每夜都要自己的电池。
- 100L 待处理水 = 16.7 瓶 6L；按 5 夜/批 → 单台约 3 个月（游戏内）消化 100L，多台更快。
- 600L 达标水 ≈ 100 个 6L 瓶 / 10 个 60L 瓶。

### 12.2 单瓶价值（按原版条件倍率推算）

| 容量 | 优质水（+50%） | 纯水（+100%） |
|---|---|---|
| 1L | ≈69 | ≈91 |
| 3L | ≈205 | ≈275 |
| 6L | ≈375 | ≈505 |
| 20L | ≈1550 | ≈2090 |
| 60L | ≈3950 | ≈5300 |

（基础 40 信用点/L × 水质倍率 × 容器底价 + 全局零售 markup≈15%；具体成交价以议价界面为准）

**60L 会不会太强（Q23 复核）：不会。** 水价 40/L 与净水器效率/配方均未修改，60L 与「30 个 2L 瓶」单位水量等价：60L 优质 = 60L×60 + `water_tank` 底价 350 ≈ **3950**；30 瓶 2L = 30×(2L×60 + 9) ≈ **3870**。大瓶只省容器与操作，真正的成本仍是净化时间与电（单台 6L 一批约 4–6 夜，60L 约 40–60 个净化夜）。因此定价按原版倍率、不做额外加权（D53），M5 再观察。
