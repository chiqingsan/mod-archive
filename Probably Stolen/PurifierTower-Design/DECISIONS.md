# DECISIONS — 净水塔设计决定与待拍板问题

> 记录「为什么这么设计」。每条决定都有理由；Q 系列是**需要用户拍板**的开放问题。
> 级别：D=已定（设计决定，可推翻）；Q=待用户确认；~~删除线~~=已被后续版本取代（保留作为历史）。
> 当前版本：**v0.8**（2026-11-01 晚，UI 评审：电池区改 4×4；完整历史见第四节「历史备注」）。

## 一、已定设计决定（D）

### 塔本体

- **D1（v0.4 改）塔外部尺寸 3×3**：店内占地 9 格（用户定）。类型 `MACHINE`，`InitMachinery(tower, 0)`：塔自身不登记固定耗电、不接店铺电网。
- **D2（v0.4 改，v0.8 再改）塔内区域**：①净水器区 **20×19 格**（只放净水器）；②UV 槽（净水箱内独立 1 槽）；③待处理区：固定内置 **100L** 水容器；④已处理区：固定内置 **600L** 水容器；⑤电池区 **4×4**（16 格）；⑥输出区 **4×7**（28 格）。各区域独立，互不混用（用户明确）。
- **D3（v0.4 改）净水箱 = 净水器区 + UV 槽 + 600L 达标水容器**：净水箱只负责自动化接线（补水/取达标水），净化本身完全是净水器的机制。

### 净化（核心，v0.4 改）

- **D4（v0.4 核心）净化由玩家净水器自己执行、自己供电**：玩家在 20×19 里放入原版净水器，给它的电池槽放电池、瓶槽放液体容器；游戏夜结自动让净水器跑 `onCycleEndSlotItemFunc`（4 电/夜，取自它自己的电池）。塔**不代跑 `PurifyContainer`、不给净水器供电、不改净水器数值**。
  - 理由：用户定「其他机制是净水器的，净水箱只负责自动化连接水净化的流程」；「净水需要代价（电量、时间）」，代价由净水器承担。
- **D5 一个净水器 = 一个瓶槽容器**：净化只发生在净水器瓶槽（body storage 索引 2）里的液体容器；塔只操作这个容器，不碰净水器其它槽。
- **D6 净化不达标就继续跑**：净水器每夜自己净化，塔不干预；多夜后达标才被塔抽走。
- **D7 ~~塔驱动 PurifyContainer~~**：v0.3 方案，已被 D4 取代（保留代码可行但不用）。

### 夜结算

- **D8（v0.4）塔用 `onCycleEndLateSlotItemFunc` 做收尾结算**：`PlayerStore.EndNight` 先跑所有机器（普通段，`PlayerStore.cs:1720`），再跑晚段（`:1728`）；塔注册晚段回调（原版先例 `VendingFountainHelper.cs:103`），保证「净水器先净化、塔后检查/转运/补水」。~~v0.2 曾计划 `OnGoingSleepLate`~~，v0.4 不再必需（可作兜底）。
- **D9 每夜结算顺序**：0) 600L 满 → 全停 + UI 提示（D42）；①抽走达标水（净水器容器 → 600L）；②空容器补水（待处理 100L 优先，其次水龙头，都没有就不动）；③UV（每次注水后一次）；④刷新 UI。
- **D10 达标判定是下限**：实际纯度 ≥ 目标档门槛即转运；单遍净化越过更高档时按**实际档位**贴标（不伪造、不浪费）。
- **D11 转运前贴真实标签**：`SetPresumedPurity(600L容器, GetWaterPurity(600L容器))`；输出瓶逐级继承，避免 `SecData.GetMislabeledWaterWeight` 判假标（合法售卖的前提）。

### 水源

- **D12（v0.4 改）待处理区 = 固定内置 100L 容器，玩家手动倒水**：不设玩家容器槽；玩家拿装脏水的容器点塔 → 把水倒进 100L 容器（剩余不接收/留在玩家容器）。理由：用户定「待处理容器槽内有一个固定的自带的水容器，容量 100L，玩家可以自己把水转移过去」。
- **D13（v0.4）补水优先级**：待处理区有水 → 用它；否则「自动水龙头」开关打开且 `EmporiumEntry.IsWaterTapUnlocked()` → 用当日水龙头水质直接注水（`AddWater`）；两者都没有 → 什么也不做（净水器空容器空转，不报错）。
- **D14 自动水龙头不经过 100L 容器**：水龙头水直接灌进净水器瓶槽容器（用户语义「没有待处理水就用水龙头」）；开关关闭或未解锁时塔永不碰水龙头；UI 上开关置灰 + tooltip。
- **D15 水龙头水质用原版当日值**：`StoreStation.Instance.todayRustwaterPurity`（9000–9150，锈水优先）或 `todayGutterflowPurity`（8000–8999），每天重掷（`StoreStation.cs:69-70`）。
- **D16 UV 自动化**：UV 槽放 `uv_filter`；每次给容器注水后 `OnUVUsed(容器)` 一次（灭 microbe，零耗电零耐久）。手动使用时保留原版行为。

### 电池

- **D17 电池区 4×4 合并电量池（v0.8 改）**：16 格，只收 `power_source_item` 且 owned；取电按顺序逐块 `PowerHelper.TryRemoveEnergy(battery, 需求量, useBandwidth:false)`（可部分抽）；能量列阵 `powerblock` 见 D50。容量与续航见 DESIGN §6 与 V10。
- **D18 电池区只供打印灌装**：净化用电由每台净水器的电池槽自理（v0.4 改；此前计划供净化+灌装）。塔本体 0 耗电。
- **D19 电池区允许放任何电池**：`energy_credit`（100 电）、`_ext`（250）、`_breeder`（每夜自充 4）、`_dis`（1000 一次性）、hypertech 电池；不排除发电设备（待 Q）。

### 灌装

- **D20 灌装 = 打印瓶 + 装水**（用户定）：点容量按钮 → 生成空瓶 → 从 600L 装水 → 扣电 → 进输出区。打印不耗材料。
- **D21 容量档 1L/3L/6L/20L/60L**：3L→`water_pitcher`、6L→`water_jug`、20L→`water_tank`（原版物品）；1L 与 60L 原版没有 → **新增两个物品，暂用游戏现有贴图占位**（用户定：暂用现有贴图）。
- **D22 电耗公式（用户定：拟合，容量越大性价比越高）**：`电 = round(3 + 0.004 × 装水量ml)` → 满瓶 1L=7、3L=15、6L=27、20L=83、60L=243；半瓶按实际装水量计（例：装一半 → 4/8/14/42/122）。校准点：原版瓶子打印机 750ml=6、2000ml=11 精确吻合。
- **D23 灌装后玩家自行处理**：塔**不做自动售卖**、不接喷泉、不自动议价；瓶子放输出区，玩家自取。
- **D24 手动直接灌满**：玩家拿**空**液体容器点塔 → 从 600L 直接灌满（不打印、不耗电）。
- **D25（v0.5 改）半瓶也灌，但最少 10ml（用户定）**：600L 余量 ≥ 10ml 即可灌装，实际装水量 = min(规格容量, 600L 余量)；瓶子按规格生成、装实际水量、按实际水量计价与扣电，之后可再补满。600L 余量 <10ml / 电量不足 / 输出区满时按钮置灰并 tooltip 说明。
- **D26 输出区 4×4**：打印瓶放入输出区（仿 `MachineBottlePrinter` 范式）。

### 目标档与品质

- **D27 目标档塔统一设置**（用户定）：普通 9800 / **优质 9900（默认）** / 纯水 9990。
- **D28 纯水依赖玩家净水器**：纯水需每台参与净化的净水器品质加成 ≥100（4×`system_fineness` 或 2×`system_capped_neural_core` 或 1×`system_uncapped_neural_core`）；塔不代堆品质，只在 UI 提示「当前净水器最高可达 X%，纯水不可达」。
- **D29 不做 100%（10000）档**：需品质 ≥200，官方极限，本 mod 不做。

### 其它

- **D30（v0.6 改）实现约束放开：不要求 0 Harmony（用户定「需要反射就反射, 要注入就注入」）**：注册优先 Harmony `Postfix FoodItemDirectory.InitDirectory`（WaterTower 1.0.8 已实机验证）+ 反射取原版工厂；上架可用 Harmony 补 Jackson 第 15 天；夜结优先 `onCycleEndLateSlotItemFunc`，时序不稳再用 Harmony `Postfix PlayerStore.EndNight` 兜底；窗口/倒水/UV/贴标/打印继续用公开 API（`MachineHelper.CreateMachineryWindow`、`TransferLiquid`/`AddWater`、`OnUVUsed`、`SetPresumedPurity`、仿 `TryPrint`）。
- **D31 滤芯仓不做**（用户定）：滤芯只在转移时截大颗粒，收益低；塔内不设滤芯槽。
- **D32 净水片不进塔**：净水片是氯化学，0.7% 地板，不补水不去重金属，game 内也非必需。
- **D33 塔内状态存 tag**：自动水龙头开关、目标档等存塔物品 tag，随存档自动保存（`SaveItemNode.itemState`）。
- **D34 内置容器不可取出**：100L 待处理、600L 达标容器都是塔子物品，玩家只能通过「倒水/灌装」操作，不能取出或替换。
- **D35 塔的贴图/形状**：3×3，先用现有贴图占位；正式美术后换 `SetSpriteAndShapeFromMod`。
- **D36 多台净水器并发**：20×19 能放几台由净水器贴图占格决定（实测）；塔逐台处理，不限制台数。
- **D37 数据刷新**：每夜结算后刷新 UI（水量、达标状态、电池余量、每台净水器状态）；不每帧轮询。
- **D38 失败静默**：`TransferLiquid` 等 API 失败不抛异常；塔侧全部前置检查（空/满/无电/无容器），失败只更新 UI 提示。
- **D39 净水器电池状态不做提示（用户定）**：净水器没电池/耗电时该台停摆即可，塔不弹提示、不高亮、不阻止；玩家自行检查。
- **D40（v0.5）净水器瓶槽容器玩家自备**（用户定）：塔不代配、不代买容器；瓶槽为空或放的不是液体容器 → 该台净水器不参与补水/转运，塔跳过并在 UI 标注该台状态（不报错、不弹窗）。
- **D41（v0.5）塔内可直接配置嵌套净水器**（用户定）：双击 20×19 区域里的净水器即打开它自己的窗口（放电池/瓶槽容器/模块），无需取出；零额外实现——游戏原生 `ItemMouseDoubleClickHandler` 对任意嵌套层级的 `contentWindow` 都生效（`ItemMouseDoubleClickHandler.cs:143-153`、`:177-203`）。M2 实机确认。
- **D42（v0.5）600L 满 → 转运与补水一起停**（用户定）：`GetFreeCapacity(600L容器) == 0` 时本夜直接跳过「检查达标 → 转运 → 补水 → UV」，只刷新 UI「已满，请灌装/取水」；净水器里的水保持原样（净水器仍自己每夜净化，可能白耗它的电——属于玩家未及时取水的代价）。
- **D43（v0.5）半瓶最少 10ml**（用户定）：600L 余量 <10ml 不允许灌装（按钮置灰 + tooltip），避免打出几乎空瓶白扣电。
- **D44（v0.6）自动水龙头开关默认关**（用户定）：塔窗口开关初始为关；未解锁时置灰；开关关着塔永不碰水龙头，只对待处理 100L 补水。
- **D45（v0.6）单一水源、不混水**（用户定）：每台净水器的瓶槽容器**只在空的时候补一次水**——这一批只能用一种水源（待处理优先；待处理没有才用水龙头）；待处理不够时**宁可不补满**；这批水达标抽走之前不再补第二种水，避免混水拉低纯度。
- **D46（v0.6）纯水不可达的净水器只做按键高亮标记**（用户定）：当某台净水器的品质加成（→ `GetMaxPurityCap` 等价值）达不到塔当前目标档时，在净水器区给它**加高亮标记**（参考「帮我上货」QuickSell：`Hints.cs`/`HintArtwork.cs`/`HintBounds.cs`，PNG 内嵌 + ≤512×512 共享图集 + 四角 UV 按格贴合）；不弹窗、不警报、不阻止运行；净化到极限后 `removed==0`，净水器当晚不扣电，不会白烧电。
- **D47（v0.6）净水器台数不设上限**（用户定）：20×19 能放几台放几台；电池玩家自费，天然限速；塔逐台按顺序处理。
- **D48（v0.6）便携净水器可放入但不生效**（用户定）：塔只把 `identifier == "water_purifier"` 的机器当参与净化的净水器；`portable_water_purifier` 放进净水器区视为无效物品，塔跳过、不报错。
- **D49（v0.6）外部交互只与 600L 储水区**（用户定）：空液体容器**点塔** = 从 600L 直接灌满（D24）；往待处理 100L 倒水必须**打开塔窗口后**与待处理容器交互，不能拿容器点塔倒进待处理区。
- **D50（v0.7）电池区允许放能量列阵**（用户定）：除电池外接受 `powerblock`（原版能量列阵，价 200；`FurnitureItemDirectory.CreatePowerBlock`，每夜 `onCycleEndEarlySlotItemFunc` 给**相邻**的电池 `PowerHelper.ChargeBattery(+2)` 或可充电机器 `MachineHelper.RechargeMachineBattery(+2)`；`IsCommercialPowerUnlocked()` 后 +4；停电事件生效时停止充能）。
- **D51（v0.7）输出区 4×7**（用户定）：28 格，容纳 60L 瓶（`water_tank` 贴图占多格）与大瓶混排。
- **D52（v0.7）UV 槽固定 1 个**（用户定）：一次全清微生物，不需要第二个。
- **D54（v0.8）电池区 4×4 + 输出区横向 4×7 + 瓶形占格**（用户定）：电池区由 8×8 改为 4×4（16 格）；输出区横向 4×7（28 格）；瓶子占格 1L 1×3 / 3L 1×4 / 6L 2×3 / 20L 2×4 / 60L 2×4。窗口按三页签固定尺寸设计（`mockup/tower-window.html`）。
- **D53（v0.7）单价/获取/美术收尾确认**（用户定）：定价按原版倍率**不削弱**（水价与净水器效率/配方均未改，60L 与 30×2L 等价，理由见 DESIGN §12.2）；获取方式 M0/M1 用开局发放过渡、M3 切 Jackson 第 15 天补丁；美术先用现有贴图占位。
