# 更好的库存排序

更好的库存排序工具（v1.3.4，适用游戏版本 0.46D）。DLL 文件名保持为英文 `SmartInventoryArrange.dll`。

- 优先排列大件、容器、机器和储藏类物品。
- 相同物品尽量连续摆放。
- 相同类型尽量集中在相邻区域。
- 通过全局布局搜索减少空洞、狭窄碎片和类别交错。
- 应用前后校验库存快照；检测到库存被外部改变时会取消操作，避免覆盖玩家的新操作。
- 应用门槛：候选布局更好、与当前布局指标持平、或空洞明显更少时都会应用；只有候选明显更差时才保留原布局，避免“点了没反应”。

## 使用方式

打开库存或展示柜后，在库存网格的空白位置打开排序菜单，再选择“智能排列”。右键点击容器物品本身只会打开游戏原有的物品菜单；整理按钮位于排序菜单中。

## 设置说明

- “保留容器排列”默认关闭。开启后，排序菜单会多出“保留容器排列”选项：把有内容窗口的容器和电源块固定在原位，只整理其他物品。关闭时菜单保持原样。

## 权限说明

该版本只需要反射权限，用于访问正式版排序窗口的内部字段；排序过程不读写任何文件。排序阶段计时会以 `Smart arrange perf:` 开头的日志行输出到 Unity 的 `Player.log`，方便排查问题。

## 性能说明

- 捕获阶段按当前帧时间自适应分帧：每帧最多使用约 35% 的帧时间（夹在 1–6 ms 之间），物品越多分摊到的帧数越多，单帧峰值不随物品数量线性增长。
- 首次排序会在后台执行完整布局搜索；之后的点击默认只在前一次结果的基础上继续探索一小批（`ResumeSolutionBatch = 16`），所以等待时间明显短于首次。
- 可移动物品达到 100 件以上时自动提高搜索预算：首次 128 个候选、续搜 32 个（`LargeSolutionBatch`/`LargeResumeSolutionBatch`），降低“保留原布局”的概率；代价是大库存等待变长。
- 物品数量达到数百件（较常见）时，首次排序的等待约 1–2 秒；之后的点击通常更快。总耗时随物品数增加属于预期行为。
- 设计上优先保证帧率平稳：分帧会让“点击→结果”的总墙钟时间略长，但避免单帧卡顿。
- 点击排序会输出 `Smart arrange click:` 日志（按钮、菜单状态、库存是否有效、是否忙碌），便于排查点击未生效的问题。
