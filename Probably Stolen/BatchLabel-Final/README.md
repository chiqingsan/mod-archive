# 标签机批量打标签

《深空当铺 / Probably Stolen》0.46D 模组。

## 功能

原版标签机一次只能改一件物品的标签。装上本模组后，装备标签机、按住触发键（默认空格）拖出批量选择框，松开鼠标左键，框内与起点**同一种物品（相同 identifier）**的物品会批量复制起点物品**当前显示的标签**：

- 起点显示的是正品 → 框内同类物品都被贴上正品标签；起点显示的是赝品 → 都被贴上赝品标签。
- 不要求先手动给起点贴标签：起点自然显示什么，就复制什么。
- 也可以先用标签机伪造标签再批量复制（例如把一件赝品标成「正品」，再以它为起点框选）。
- 起点处于「已被揭穿」状态时，复制它当前显示的真实条件。
- 只处理框内与起点同类型的物品，框内的其它物品不受影响；起点物品本身不会被改动。
- 不按触发键、或没有装备标签机时，原版行为完全不变。
- 触发键可在 **游戏设置 → 按键 → 修改标签机批量打标签的快捷键** 中修改，设为 `None` 可停用。

### 标签记忆（右键快捷打标签）

用标签机给某类物品打过标签后，本模组会把这次的选择记住：

- 记录时机：在标签机界面里每改动一个标签槽位，就记下「这类物品的这个标签分类应该贴成什么」。
- 套用时机：装备标签机时**右键**同类物品，立刻按记忆把标签贴上去，并**保持装备**，方便接着给下一件打标签。
- 记忆按物品类型（identifier）分开保存，不同类型的物品互不影响；同一个标签分类以最后一次选择为准，不同分类各自累积。
- 例：给咖啡片打上「实验室纯级」→ 之后每次装备标签机右键咖啡片，都会直接变成实验室纯级。
- 记忆写在模组配置文件里，跨游戏重启保留。
- 右键空地、或右键「这类物品还没记过标签」时，仍是原版行为（右键取消装备）。

## 边界行为

| 情况 | 行为 |
| --- | --- |
| 起点没有可编辑的标签槽位（原版标签机也不能编辑它） | 不接管，按原版行为处理 |
| 起点没贴过标签 | 复制它当前显示的条件（正品 → 正品标签，赝品 → 赝品标签） |
| 起点已被揭穿 | 复制它当前显示的真实条件 |
| 框内有其他类型的物品 | 只给与起点同 identifier 的物品打标签 |
| 框内没有任何起点类型的物品 | 不做任何改动 |
| 框不够大、起点物品没被框进去 | 仍按起手位置反查起点物品，正常对框内同类型物品生效 |
| 框内物品已经显示同样的标签且未被揭穿 | 不重复写入（避免重复触发标签的改名/改价动作） |
| 框内物品的标签已被揭穿 | 重新按起点贴上标签 |
| 框内只剩起点自己 | 不做任何改动 |
| 起点或框内物品不是自己的（无 `IS_OWNED_TAG`） | 不接管 / 不写入，与原版标签机目标条件一致 |
| 装备标签机右键同类物品，且这类物品记过标签 | 按记忆重新贴上标签，标签机保持装备 |
| 装备标签机右键没记过标签的物品、或右键空地 | 原版行为：取消装备 |
| 装备标签机右键标签机自己 | 原版行为：取消装备 |
| 只打开标签机界面看一眼就关掉 | 打开时的初始选中不算玩家的选择，不会覆盖已有记忆 |
| 记忆里的标签分类/条件在当前游戏版本已不存在 | 跳过该条记忆，不报错 |

## 安装

把 `BatchLabel.dll`、`manifest.xml` 一起放进：

```
<游戏目录>\Mods\BatchLabel\
```

（`preview.png` 可选，用于模组列表预览图。）

## 说明

- 写入语义与游戏原生标签机 UI 一致：写入假条件（`ItemFeature.fakeCondition`）并把标签设为「未揭穿」；水质标签（`CATEGORY_WATER_PURITY`）额外复制 `customIntValue1`，和标签机 UI 的下拉框行为一致。
- **装备不会被弄丢**：按下左键起手框选的那一瞬间，游戏会把标签机「取消装备」（这是原版机制：装备中的工具会让框选处理器收不到鼠标事件，必须先卸下），本模组在框选落定或取消后会自动把标签机重新装备回去。
- 默认触发键空格同时是游戏的「推进对话」键：按住空格时可能顺带推进一次对话（和「按键拖拽多选框」模组的已知副作用相同）。介意的话到 **游戏设置 → 按键** 把触发键改成别的键。
- 复制始终写在目标的「假条件」上：目标会显示成起点当前显示的样子，而它的真实条件不变——这正是把赝品伪装成正品的用法。
- 只改标签显示，不改变物品的数量、位置或归属。
- 与「按键拖拽多选框」（BatchSelect）兼容：两个模组同时安装可以共存。注意两者默认都用空格，且都支持从物品上起手框选；同时按住空格从物品上起手时，本模组会在框选落定后按上述规则批量复制标签（框内物品可能因此显示成起点的标签）。只想用其中一个功能时，把触发键改成不同按键即可。
- 蓝色标签机改的是自定义名字，不是本模组处理的范围。
- 标签记忆存在模组自己的配置里（`Probably Stolen_Data` 下的 `ModConfigs/chiqingsan.BatchLabel.json`），所以**不需要额外的文件读写权限**。模组设置里会看到一项「已记住的标签（自动保存，请勿手动修改）」，那是自动保存的数据，手动改动会让该项记忆失效。
- 右键套用记忆和批量复制写的是同一套东西：改假条件 + 设为未揭穿，水质标签连 `customIntValue1` 一起写。

## 实现

- Harmony patch `ItemMultiSelectHandler.FinalizeBand`（框选落定）：用反射读取起手位置 `pressPosition` 反查起点物品，收集起点各标签槽位当前显示的条件，批量写入框选列表里同 identifier 的物品，然后结束这次框选。
- Harmony patch `ItemMultiSelectHandler.OnEventPress`：装备标签机 + 按住触发键 + 左键按在可打标签的物品上时，手动把原版处理器置入「待框选」状态（原版只在起点无物品时才会进入该状态）。
- Harmony patch 四个会在同一帧处理左键按下的处理器（`ItemMouseDragHandler` / `ItemMouseDoubleClickHandler` / `ItemDefaultActivateHandler` / `ItemSelectHandler`），从物品上起手框选时跳过它们，避免打开标签机 UI、拖动物品或触发单击交互。
- 按下时记录「起手物品 + 当前装备的标签机」，框选落定后据此批量打标签（不再依赖实时的装备状态）；框选落定/取消后调用 `ItemSelectHandler.TryEquipItem` 把标签机重新装备回去（`OnEventRelease` / `OnEventReset` 兜底）。
- 接管状态带跨帧校验：只有同一按下帧内、或框选仍在进行时才复用「已接管」记录，其它情况视为陈旧状态并先恢复装备，避免别的模组抢断输入循环后出现「幽灵接管」。
- 起点与写入目标都要求 `GeneralHelper.IsItemOwned`，与原版标签机目标条件（自有 + 有可编辑标签槽位）一致。
- patch `GameOptionRegistry.EnsureVanilla`，把触发键选项追加到游戏原生按键设置里；触发键值保存在模组配置文件中。
- 标签记忆：patch `LabelerUIManager.OpenUI` / `LabelerElement.OnDropdownValueChanged` / `LabelerUIManager.CloseUI`。玩家在标签机界面里改标签时，用反射读 `LabelerElement.thisFeature` 与 `LabelerUIManager.curItem`，把「物品 identifier → 标签分类 → 条件」记进内存；关闭界面时序列化成单行文本写进模组配置项 `LabelMemory`。打开界面那一帧的程序化初始选中用帧号守卫跳过，即使收尾补丁没执行，守卫也会在下一帧自然过期，不会永久停止记录。
- 右键套用：在 `ItemSelectHandler.OnEventPress` 的前缀里判定「右键 + 装备标签机 + 鼠标下一件记过标签的自有物品」，命中就套用记忆标签、播标签音效并返回 false 跳过原版逻辑（因此标签机不会被取消装备）；没命中则照旧走原版右键取消装备。

不开启新线程、不做每帧扫描；只在按键按下和框选落定的事件里工作。

## 验证

- `BatchLabel-Final.Tests`（net6.0 控制台工程，直接编译 `LabelBatch.cs` + `LabelMemory.cs` + 游戏类型 stub）覆盖了上表的边界行为、正品/赝品双向复制、已揭穿物品、同类型过滤、水质标签复制、避免重复触发动作，以及标签记忆的覆盖/累积/序列化往返/损坏数据容错/条件失效跳过/右键套用等共 22 项。
- 实机验证需要：装备标签机 → 按住空格从一件物品上拉框到多件同类型物品并松开，确认框内同类物品显示成起点当前的标签；再分别验证起点没贴过标签、框内混入其他物品、框内无同类型物品这三种情况。
- 标签记忆实机验证：用标签机给咖啡片选「实验室纯级」→ 关掉界面 → 装备标签机右键另一件咖啡片，确认直接变成实验室纯级且标签机仍装备；再右键没记过标签的物品与空地，确认仍是原版取消装备；重开游戏后再右键一次，确认记忆仍在。

## 更新记录

- 1.0.3：新增标签记忆。用标签机给某类物品打过标签后，本模组会记住这类物品的标签；之后装备标签机右键该类物品即可按记忆重新贴上，并保持装备。记忆按物品类型保存、跨重启保留，存在模组配置里，不新增文件权限。

- 1.0.2：代码加固。接管状态增加跨帧校验，避免其它模组抢断输入循环后残留「幽灵接管」；起点与写入目标增加物品归属校验（`IS_OWNED_TAG`），与原版标签机目标条件一致；去掉重复的屏幕射线。
- 1.0.1：修复「按住触发键从物品上起手框选时，标签机被取消装备」的问题。原因是原版 `ItemSelectHandler` 在装备状态下会阻断框选处理器的鼠标事件，本模组必须先重置它；现在会在按下时记录装备的标签机，框选落定或取消后自动重新装备。
- 1.0.0：首个版本。复制起点物品**当前显示的标签**（正品/赝品双向），框选内只处理与起点同 identifier 的物品。
